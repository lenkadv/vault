# Marketing strategy quality checklist

Score each line yes or no. One no means the run is not complete.

## Session proof (session mode)

- [ ] Six sections; plan proof; honest missing results; delegated actions.
- [ ] Reconcile ran before the session facts were assembled.
- [ ] "Since the last session" used a proven boundary.
- [ ] Shipped items had verified published receipts inside that period.
- [ ] Waiting and stuck items matched their current metadata and logbook events.
- [ ] Unknown approval age stayed unknown.
- [ ] The recommendation cited a real priority from the selected business's `brain/plan.md`.
- [ ] Missing results produced no numbers or performance story.

## Plan proof (plan-edit mode, and any run that touched the plan)

- [ ] Every plan change ran the maintain small/big sort; big changes went through the full round in `playbooks/create.md`, through the review queue.
- [ ] Every number on the page traces to a named brain file, the owner's words this session, or shown arithmetic; everything else is a `[PLACEHOLDER: ...]`.
- [ ] No placeholder was filled, softened, or deleted.
- [ ] The page stayed at or under about 500 words.
- [ ] Every status or landing claim was read back from disk before it was said.

## Close-out

- [ ] `brain/plan.md` was checked current at the end, whatever the mode.
- [ ] Only owner-confirmed decisions were logged to `brain/decisions.md`; open ones were named as open.

## Ownership

- [ ] Item decisions were delegated to `review-queue`.
- [ ] Copy and analytics requests were handed to matching specialist skills.
- [ ] The run itself made no outside-platform write.
- [ ] The prepare question was asked no more than once.
- [ ] The prepare batch contained only items approved in this session.
- [ ] Every preparation action was delegated to `publish` or `ads-meta-publish`.
