# Theme Craft — What Makes a Good Quarterly Theme

The theme + priorities structure is doing a specific job: it captures the user's INTENT for the quarter in a way that survives contact with daily life. Most quarterly themes fail in predictable ways. This file is how to push for themes that actually shape the quarter.

## What a theme IS

A theme is a one-line, verb-led, focused intent that the user can hold in their head all quarter. Examples:

- "Build distribution" (verb-led, specific direction)
- "Ship product v2" (specific outcome with movement)
- "Health reset" (acknowledges current state + direction)
- "Hiring season" (frames the quarter)
- "Get out of the weeds" (operational vs. strategic shift)
- "Simplify everything" (subtractive intent)

The user should be able to write the theme on a sticky note and have it mean something on the 30th day.

## What a theme IS NOT

### Not a goal restatement

❌ "Increase revenue by 30%"
✅ "Pricing rebuild" (the work that produces the revenue increase)

A theme captures the DIRECTION of work; goals capture specific targets. The priorities under the theme are where the targets live.

### Not corporate-speak

❌ "Drive synergistic alignment across stakeholder groups"
✅ "Get the team rowing together" or "Clear the cross-team friction"

If the theme reads like a slide-deck bullet, push back. The user should use words they'd actually say to a friend.

### Not a vague feeling

❌ "Be more present"
✅ "Family-first Q3" or "Reset boundaries on after-hours work"

Vague feelings don't drive action. Themes need enough concreteness that the user can recognize when they're on or off it.

### Not a 12-month thing

❌ "Build a legacy"
✅ "Ship the book draft" (a 90-day cut of a long-term direction)

A theme covers 90 days. If it requires 2 years, the theme should be the 90-day slice.

### Not an everything theme

❌ "Personal growth"
✅ "Develop the speaking skill" or "Read one book per month, deeply"

If a theme could mean anything, it means nothing.

## The 1-3 rule

Themes work if there are FEW of them. 1-3 maximum. Push back hard at 4+.

Reason: the point of themes is to focus attention. 5 themes is no different from no themes — the user has to pick anyway when life happens. Picking up front (3 themes max) makes the picking deliberate. Picking in the moment (because there are 7 themes and only time for 3 this week) makes the picking accidental.

If the user wants to list 5 themes, ask: "If you had to pick the 3 that mattered most for next quarter, which would they be? The other 2 can be priorities under one of the 3, or saved for next quarter."

## The 3-5 priorities per theme rule

Under each theme: 3-5 specific priorities the user wants done in 90 days.

A good priority is:
- **Specific** — names a concrete outcome
- **90-day-achievable** — doable in one quarter
- **Theme-aligned** — clearly serves the theme

### Specific, not vague

❌ "Work on the newsletter"
✅ "Newsletter to 10,000 subscribers"

❌ "Get healthier"
✅ "Run 3x per week, every week"

### 90-day-achievable

❌ "Become a public speaker" (years)
✅ "Give 3 talks this quarter, with the third one being to 50+ people"

❌ "Build a sustainable revenue base"
✅ "Hit $X monthly recurring by end of quarter"

If a priority is genuinely a 2-year project, the priority should be "the 90-day cut" of it.

### Theme-aligned

If the theme is "Build distribution" and the priority is "redo the office furniture," there's a mismatch. Either the priority is wrong for this theme or there's a hidden 4th theme the user hasn't named.

Ask: "How does this priority advance the theme?" If the answer doesn't land, surface the mismatch.

## Metrics are optional

Some priorities have natural metrics:
- Subscriber counts
- Revenue numbers
- Workout counts
- Page counts of written work

Others don't:
- "Get better at presenting"
- "Have more meaningful conversations with my partner"
- "Improve technical depth"

For natural-metric priorities, capture the metric. For not-natural-metric priorities, accept "I'll just know."

Don't manufacture metrics. A bad metric (e.g., "have 1 meaningful conversation per week" for the relationship priority) gamifies something that shouldn't be gamified.

## Common theme patterns

### Building / launching themes

For ship-the-thing quarters. Theme is the thing being built; priorities are the milestones.

Example:
- Theme: "Launch the course"
- Priorities: Build module 1, beta test with 10 people, launch landing page, hit 50 sales

### Subtraction themes

For too-much quarters. Theme is the cut; priorities are what gets dropped.

Example:
- Theme: "Cut to focus"
- Priorities: Drop 3 active projects, reduce meeting load by 30%, cancel 2 recurring commitments, clear next-actions queue weekly

### Resetting / recovery themes

For burnout-prevention quarters or post-intense periods.

Example:
- Theme: "Health reset"
- Priorities: Sleep 8 hours weekday baseline, run 3x/week, cook dinner Mon-Thu, no work email after 18:00

### Capability themes

For skill-development quarters.

Example:
- Theme: "Sharpen the writing"
- Priorities: Publish 1 long-form post per month, finish [book on craft], do morning writing 5 days/week, edit existing drafts (3 of them) to publishable

### Relationship themes

For when relationships are the priority.

Example:
- Theme: "Show up for [person]"
- Priorities: Weekly date night, one meaningful conversation per week (no logistics), shared trip planned, address the [topic] we've been avoiding

### Strategic shift themes

For when the work direction is changing.

Example:
- Theme: "Get out of the weeds"
- Priorities: Hire ops manager, delegate Y, redesign team structure, spend 50% of time on strategic work (currently 15%)

## When themes feel wrong

If the user picks themes but they feel hollow when read back, that's signal. Common reasons:

- **The user doesn't actually want what the theme says.** The theme is what they think they should want. Push: "Is this what you want, or what you feel you should want?"
- **The theme is too general.** Replace with a more specific version.
- **The theme is too ambitious.** A 90-day slice would feel better.
- **There are too many themes.** Cut.

Reflection helps. Sometimes the right move is: "Let's come back to this. Sit with it overnight. The themes you settle on tomorrow will probably be sharper."

## The test for a good theme set

At the end of Session 3, the user should be able to:

1. State the themes from memory (without looking)
2. Explain WHY each theme matters to them (not from a script)
3. Picture what success looks like at the end of the quarter under each theme

If any of those three break down, the themes need more work.
